# 任务

请判断：该产物是否满足上述**验收标准**？

## 文本类产物（.md / .json / .srt / .txt 等）
- **通过**：产物路径存在、内容与任务描述及验收标准一致或可接受 → `accepted=true`，`reason` 简短说明通过理由。
- **不通过**：产物缺失、内容明显不符或质量不达标 → `accepted=false`，`reason` 写明不通过原因。

## 二进制类产物（.png / .jpg / .mp4 / .wav 等）
当摘要为「二进制文件，大小 xxx bytes」时，**不要按文本内容判断**。请根据以下规则：
1. **存在性**：产物路径由系统给出（见上方「产物路径」），若系统已填写具体路径且摘要中给出大小，可认为文件存在；若路径为「（无）」或摘要为「（无产物文件）」则视为缺失。
2. **大小**：摘要中「大小 N bytes」若 N > 0，则视为非空文件；若为 0 或未给出则视为无效。
3. **后缀**：路径后缀应与任务要求一致（如视频任务应为 .mp4/.webm 等，图片应为 .png/.jpg 等）；若任务未明确格式，常见媒体后缀可接受。
4. **格式校验（可选）**：若你知晓环境中有 ffprobe（音视频）、identify（图片）等工具可用于校验文件头，可在 reason 中建议后续用其做格式校验；无则仅按 1～3 判断即可。

- **通过**：存在性、大小>0、后缀与任务一致 → `accepted=true`。
- **不通过**：路径缺失、大小为 0、或后缀明显与任务不符 → `accepted=false`，`reason` 写明原因。

# 输出格式

仅输出一个 JSON 对象，无其他文字、无 Markdown 代码块。格式：`{"accepted": true或false, "reason": "简短说明"}`
